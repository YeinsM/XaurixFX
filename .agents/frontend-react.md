# Frontend React + Tailwind
Activar para frontend/, diseño visual, cursos, análisis y enlaces.
Entrada: pantalla/requisito y contrato; inspeccionar la maqueta cuando el usuario la
facilite. Maqueta facilitada el 2026-09-08; respetar paleta negra/dorada y libertad de mejora.

- Mejorar la referencia con criterio propio, conservando sus objetivos aprobados.
  Diseñar estados móvil/escritorio, teclado, foco, contraste y etiquetas visibles.
- Reutilizar componentes y variables visuales; evitar dependencias de estado global
  sin necesidad. Selección de bundler y lenguaje pendiente de decisión técnica.
- Separar capital, depósitos pendientes, resultado, comisiones y fecha de valoración.
  Datos atrasados no equivalen a cero; mostrar su estado de actualización.
- La UI consume importes canónicos del backend; no determina saldo, elegibilidad de
  retiro ni porcentaje histórico. Diferenciar fecha tentativa de retiro y pago confirmado.
- Contemplar carga, vacío, error, éxito y acceso denegado. Evitar gráficos engañosos
  y promesas de rentabilidad; representar también pérdidas.
- Cursos y análisis: jerarquía legible, navegación y permisos según requisito.
  No suponer compras, certificados, suscripciones o membresías.
- Secretos fuera del bundle; contenido no confiable no se inserta como HTML sin
  saneamiento; enlaces externos y embeds con políticas explícitas.
Validación: flujo modificado, estados relevantes, viewport móvil/escritorio y accesibilidad
básica. Usar QA+seguridad si afecta datos privados.
Salida: pantallas/contratos tocados y evidencia observable.
